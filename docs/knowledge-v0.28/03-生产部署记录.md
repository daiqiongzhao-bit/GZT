## 6. 遗留问题（需你确认后执行）

### L-02【中低风险】服务器 `.git/config` 明文 GitHub Token

**现状**（本次部署期间新确认）：

```
/root/GZT/.git/config   权限 644 root:root   内含 ghp_5P0W... 明文 token
/root/KCBD/.git/config  同样问题
```

**风险评估**：
- ✅ token 未被 git 跟踪，不会随代码外泄
- ⚠️ 权限 644，同机任何用户可读
- ⚠️ **两个仓库**同时存在该问题
- ⚠️ 注意：本地 push 通道是 `ssh root@49.51.200.165`，GitHub token 实际仅供服务器 → GitHub 使用

**整改建议**（三选一，**等你确认**）：

| 方案 | 操作 | 影响 |
|---|---|---|
| A. 改权限（最小改动） | `chmod 600 /root/GZT/.git/config /root/KCBD/.git/config` | 无副作用，但仍为明文 |
| B. 换 SSH 密钥（推荐） | 生成部署密钥 → GitHub 配置 Deploy Key → 移除 token | 需改 remote URL，一次性 |
| C. 仅吊销 token | GitHub 后台 revoke `ghp_5P0W...` | 会中断服务器 push 能力 |

**我的建议：A + B 组合** —— 先 `chmod 600` 立刻止血，再迁移到 Deploy Key 彻底解决。

⚠️ 涉及凭据变更，按你的习惯**我不擅自动手**，请回复方案编号。

## 7. 本次部署新发现的经验（建议写入运维手册）

1. **生产路径是 `/root/GZT`，不是 `/opt/gzt`**（后者不存在，`/opt/gzt-demo` 是独立 demo）
2. **宿主端口是 8090**，不是 8080；`localhost:8080` 被另一个旧 docker-proxy 占用（pid 1741480），排查时勿混淆
3. **前端产物 embed 进二进制**，找不到 `dist/` 目录是正常的，验证应抓 HTTP 资源而非查磁盘
4. **验证前端产物要看 `Workspace-*.css/js`**，`index-*.css` 只是全局样式（27 KB），据此判断"构建不完整"会误判
5. 构建日式打印 `CACHED` 出现在基础层（node/golang 镜像、`pnpm i -g`）属正常，**关键看 `frontend 6/7` 是否真实执行 `vite build`**
