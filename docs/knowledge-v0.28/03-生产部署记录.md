## 6. 遗留问题（需你确认后执行）

### L-02【中低风险】服务器 `.git/config` 明文 GitHub Token

**现状**（本次部署期间新确认）：

```
/root/GZT/.git/config   权限 644 root:root   内含 ghp_5P0W... 明文 token
/root/KCBD/.git/config  同样问题
```

**风险评估**：
- ✅ token 未被 git 跟踪，不会随代码外泄
- ⚠️ 权限 644，同机任何用户可读
- ⚠️ **两个仓库**同时存在该问题
- ⚠️ 注意：本地 push 通道是 `ssh root@49.51.200.165`，GitHub token 实际仅供服务器 → GitHub 使用

**整改建议**（三选一，**等你确认**）：

| 方案 | 操作 | 影响 |
|---|---|---|
| A. 改权限（最小改动） | `chmod 600 /root/GZT/.git/config /root/KCBD/.git/config` | 无副作用，但仍为明文 |
| B. 换 SSH 密钥（推荐） | 生成部署密钥 → GitHub 配置 Deploy Key → 移除 token | 需改 remote URL，一次性 |
| C. 仅吊销 token | GitHub 后台 revoke `ghp_5P0W...` | 会中断服务器 push 能力 |

**我的建议：A + B 组合** —— 先 `chmod 600` 立刻止血，再迁移到 Deploy Key 彻底解决。

⚠️ 涉及凭据变更，按你的习惯**我不擅自动手**，请回复方案编号。

### 9.1 修复内容

| Bug | 现象 | 根因 | 修复 |
|---|---|---|---|
| **Bug 1 保存后乱** | 写好知识库保存后排版错乱 | 后端 `sanitizeRichContent` 的 `safeStyleValue` 对所有 style 值拦截单引号，导致 Word 粘贴常见的 `font-family:'Times New Roman', serif` 整条被丢弃，正文所有字体声明在保存后丢失 | 仅对 `font-family` 放行单引号（其余 key 仍拦截引号防逃逸）；style 输出层对残留双引号转义为 `&quot;`；前端 `kbFilterStyle` 校验前先做实体解码（`&quot;`/`&#39;`）与后端对齐 |
| **Bug 2 按钮被挤出** | 内容写多后底部「取消/保存」下移、不可见 | 知识库三栏 `.kb-3col` 只定义了 `grid-template-columns` 未定义行高，内容变长时 `align-content:stretch` 不可靠，右栏 `height:100%` 退化成内容高度，整栏长高，底栏被挤出 `.kb-shell`(overflow:hidden) 视口 | 显式 `grid-template-rows: minmax(0,1fr)`；右栏 `.kb-detail-pane` 加 `min-height:0` 允许收缩；底栏 `.kb-detail-foot` 加 `position: sticky; bottom:0` 极端兜底 |

### 9.3 ⚠️ 关键坑：Docker 层缓存导致前端分块产物缺失（本次已修复）

- 首次 `docker compose build`（带缓存）构建出的 `daiqiongzhao/gzt:v0.28.1` 镜像，**嵌入的 `backend/web/dist` 是不完整的旧产物**：
  - 线上只服务到入口 chunk `index-BEmvvN1H.css`(27 KB) + `index-DEMp7_SY.js`(91 KB) + `vendor`；
  - **所有路由级懒加载分块全部缺失**：`Workspace-*.css/js`、`tiptap-*.js`、`Schedule/Settings/Tasks/...` 均不在镜像内；
  - 表现：CSS 里没有 `kb-3col`/`kb-detail-pane`（还是老的单栏 `kb-view` 布局），JS 里搜不到 `kb-3col`。
- 经服务器手动 `pnpm build` 确证：**源码本身能正确产出完整分块**（`Workspace-cb3FfFJ5.css` 58 KB 含 `kb-3col`、`Workspace-Bo-ErEQB.js` 132 KB、`tiptap-DbvCxdZz.js` 446 KB 全部到位），所以问题出在 `docker compose build` 的层缓存复用，而非代码。

> 🔧 **运维铁律（写入本记录）**：GZT 后续每次部署**统一用 `docker compose build --no-cache`**，不要用带缓存的 `docker compose build`/`up -d`（后者在镜像已存在同名 tag 或层命中时会跳过前端重建，嵌入陈旧前端）。代价是构建多 1~2 分钟，换来前后端产物一致。
