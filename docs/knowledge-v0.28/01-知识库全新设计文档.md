## 0. 一页看懂（30 秒速览）

**要解决的问题**：现有编辑器全部依赖已被浏览器标记为废弃的 `document.execCommand`，只支持加粗/斜体/下划线/标题/列表/左中右对齐，**没有**字号、字体、颜色、行距、缩进、撤销重做、查找替换、表格增删行列、图片缩放。用户要的"Word 常用功能"，现状只能覆盖约 **40%**。

**方案一句话**：用 **Tiptap 3.31.3（ProseMirror）** 重写编辑器内核，后端**放开 Word 常用样式白名单**（并把一个已存在的高危缺陷一并修掉），前端改成**三栏式知识库工作区**（导航 / 列表 / 详情-编辑）。**存储仍是 HTML 字符串，存量数据零迁移。**

**三条必须同批处理的红线**（拆开做等于白做）：

| # | 位置 | 问题 | 后果 |
|---|---|---|---|
| 1 | `backend/.../sanitize.go:69-75` | style 值含危险函数时 `return m` **原样放行整条样式**，绕过白名单 | 放开样式白名单后危害被放大 |
| 2 | `frontend/.../Workspace.vue:932` | `safeHtml()` **无条件删掉所有 style** | 详情页字号/颜色全被剥光，与编辑器所见不一致 |
| 3 | `frontend/.../RichTextEditor.vue` | 必须透传 `data-att-id`/`data-temp-id`/`data-att-name` | 新建条目粘贴的图片**保存后全成死链**，附件表无记录 |

**交付节奏**：本文档确认 → 分 5 步编码（每步可独立验收）→ 出《测试验收报告》→ 发 v0.28.0。

### 1.2 三个结构性问题

**问题一：`execCommand` 已被废弃。**
`document.execCommand` 自 2020 年被 MDN 标记为 Deprecated，Chromium 保留但行为不再演进。具体在本项目中的表征：
- 无法自定义撤销粒度（浏览器按 DOM 变更自动分组，用户改一段文字按 Ctrl+Z 可能退回三类操作）
- `queryCommandState` 在空选区/嵌套结构下返回不准，工具栏高亮会"粘住"
- 无法插入结构化节点（图片只能靠 `insertHTML` 拼串，导致属性丢失）

技术债证据：`RichTextEditor.vue` 中 8 处 `execCommand` / 3 处 `queryCommandState` / 零处结构化节点操作。

**问题二：后端样式白名单只有 16 项，且存在高危缺陷。**

`sanitize.go:47-52` 的 `safeStyleKeys` 仅 16 项（对齐 + 留白 + 列表 + 行高 + 字重）。这意味着**即使前端做得出字号按钮，内容一保存就会被后端剥掉**。

更严重的是 `sanitize.go:69-75`：

```go
if strings.Contains(strings.ToLower(body), "javascript") ||
    strings.Contains(strings.ToLower(body), "expression") ||
    strings.Contains(strings.ToLower(body), "@import") ||
    strings.Contains(strings.ToLower(body), "url(") ||
    strings.Contains(strings.ToLower(body), "behavior") {
    return m          // ← 返回整条 style 原文，与净化意图完全相反
}
```

**这段代码的语义是"检测到危险就放行"，而不是"检测到危险就剥离"。** 攻击者只要在 style 里塞一个 `url(`，整条 style 就绕过白名单原样落库。当前危害有限的唯一原因是白名单本身很窄、前端也不产出复杂样式；**一旦本次放开白名单，这段代码会立刻变成真实漏洞**。

**问题三：展示端与编辑端口径不一致。**

`Workspace.vue:932`：

```js
s = s.replace(/\sstyle\s*=\s*(?:"[^"]*"|'[^']*')/gi, '')   // 删除所有 style
```

后端刚放开的白名单样式，到详情页渲染时被前端整条删掉。用户会看到"编辑器里是 18px 红色，保存后变成默认黑 14px"。**这条必须与后端同批改，否则第一步白做。**

### 1.3 改动边界（明确不做什么）

| 不做的事 | 原因 |
|---|---|
| 不把存储改成 Markdown / JSON 文档模型 | 零迁移是本次硬约束；HTML 字符串链路（导出 .doc/.md/.txt、变更日志、FTS5）全部现成可用 |
| 不引入代码块语法高亮（lowlight/highlight.js） | 省约 100KB；本项目代码块场景少（用户已确认） |
| 不做协同实时编辑（CRDT / Yjs） | 本次只做"协作者权限"（v0.27.0 已完成），不做光标同步。引入 Yjs 会推翻 HTML 存储模型 |
| 不做全库 HTML 归一化脚本 | 靠"首次编辑自动归一化"（§5.4），零批量写库风险 |
| 不承诺 Word 复杂文档像素级还原 | 尽力而为；保留现有 `pasteWarn` 提示（用户已确认） |

### 3.3 自定义 Image 扩展（兼容红线）

**背景**：`backend/internal/handlers/workspace.go:1391-1455` 的 `adoptTempAttachments()` 用正则 `data-temp-id="(\d+)"` 扫描正文来找需要"转正"的临时附件。若 Tiptap 默认 Image 扩展把 `data-temp-id` 当未知属性丢弃：

```
用户新建条目 → 粘贴 3 张图 → 正文有 data-temp-id 但 getHTML() 丢掉了
  → 保存时正则扫不到 → 文件留在 temp 目录 → 附件表无记录
  → 图片 src 仍指向 /temp-attachments/... → 后续清理任务删除文件 → 死链
```

因此必须自定义：

```js
// frontend/src/components/editor/ImageAttrs.js
import Image from '@tiptap/extension-image'

export const ImageAttrs = Image.extend({
  addAttributes() {
    return {
      ...this.parent?.(),                                  // src / alt / title
      // —— 以下三个属性为「附件转正机制」依赖，不可删 ——
      'data-att-id':   { default: null, parseHTML: el => el.getAttribute('data-att-id'),
                         renderHTML: a => a['data-att-id']   ? { 'data-att-id': a['data-att-id'] }     : {} },
      'data-temp-id':  { default: null, parseHTML: el => el.getAttribute('data-temp-id'),
                         renderHTML: a => a['data-temp-id']  ? { 'data-temp-id': a['data-temp-id'] }   : {} },
      'data-att-name': { default: null, parseHTML: el => el.getAttribute('data-att-name'),
                         renderHTML: a => a['data-att-name'] ? { 'data-att-name': a['data-att-name'] } : {} },
      // —— 图片缩放与对齐（Word 常用）——
      width:  { default: null, parseHTML: el => el.getAttribute('width')  || (el.style.width  ? parseInt(el.style.width)  : null),
                renderHTML: a => a.width  ? { width: a.width }  : {} },
      height: { default: null, parseHTML: el => el.getAttribute('height') || (el.style.height ? parseInt(el.style.height) : null),
                renderHTML: a => a.height ? { height: a.height } : {} },
      'data-align': { default: null, parseHTML: el => el.getAttribute('data-align'),
                      renderHTML: a => a['data-align'] ? { 'data-align': a['data-align'] } : {} },
    }
  },
  addNodeView() {
    return ({ node, getPos, editor }) => {
      const wrap = document.createElement('div')
      wrap.className = 'kb-img-wrap'
      wrap.dataset.align = node.attrs['data-align'] || 'left'
      const img = document.createElement('img')
      img.src = node.attrs.src
      if (node.attrs.width) img.setAttribute('width', node.attrs.width)
      wrap.appendChild(img)

      // 右下角拖拽手柄：等比缩放，写回 width 属性
      const handle = document.createElement('span')
      handle.className = 'kb-img-resize'
      wrap.appendChild(handle)
      handle.addEventListener('mousedown', (e) => {
        e.preventDefault()
        const startX = e.clientX
        const startW = img.getBoundingClientRect().width
        const onMove = (ev) => {
          const w = Math.max(48, Math.round(startW + (ev.clientX - startX)))
          img.setAttribute('width', String(w))
        }
        const onUp = () => {
          document.removeEventListener('mousemove', onMove)
          document.removeEventListener('mouseup', onUp)
          const pos = getPos()
          if (typeof pos === 'number') {
            editor.view.dispatch(editor.view.state.tr.setNodeMarkup(pos, null, { width: parseInt(img.getAttribute('width'), 10) }))
          }
        }
        document.addEventListener('mousemove', onMove)
        document.addEventListener('mouseup', onUp)
      })

      // 点击图片 → 小浮层：左/中/右对齐 + 25%/50%/100% + 删除
      img.addEventListener('click', () => { /* 见 §4.4 浮层实现 */ })

      return { dom: wrap }
    }
  },
}).configure({ inline: false, allowBase64: false, HTMLAttributes: { class: 'kb-img' } })
```

**设计决策：对齐用 `data-align` 属性而非 `style="float:..."`。**
理由：`float` 不在样式白名单内，且 `float` 会脱离文档流、与 ProseMirror 的节点模型冲突。用 `data-align` + CSS 生效，展示端与编辑端共用同一条 CSS 规则，所见即所得。

```js
// editor/Indent.js
import { Extension } from '@tiptap/core'

export const Indent = Extension.create({
  name: 'indent',
  addGlobalAttributes() {
    return [{
      types: ['paragraph', 'heading'],
      attributes: {
        indent: {
          default: 0,
          parseHTML: el => parseInt(el.getAttribute('data-indent') || '0', 10) || 0,
          renderHTML: a => (a.indent ? { 'data-indent': a.indent } : {}),
        },
      },
    }]
  },
  addCommands() {
    const setIndent = (delta) => ({ tr, state, dispatch }) => {
      const { from, to } = state.selection
      let changed = false
      state.doc.nodesBetween(from, to, (node, pos) => {
        if (!['paragraph', 'heading'].includes(node.type.name)) return
        const cur = node.attrs.indent || 0
        const next = Math.min(8, Math.max(0, cur + delta))   // 封顶 8 级
        if (next !== cur) { changed = true; if (dispatch) tr.setNodeMarkup(pos, null, { ...node.attrs, indent: next }) }
      })
      return changed
    }
    return { indent: () => setIndent(+1), outdent: () => setIndent(-1) }
  },
  addKeyboardShortcuts() {
    return {
      Tab: () => (this.editor.isActive('listItem') ? false : this.editor.commands.indent()),
      'Shift-Tab': () => (this.editor.isActive('listItem') ? false : this.editor.commands.outdent()),
    }
  },
})
```

> `Tab` 在列表内不拦截（交回给 ListKeymap 处理"sink list item"），避免破坏列表体验。

### 5.2 修复 `stripUnsafeStyle` 缺陷（安全必修）

```go
func stripUnsafeStyle(s string) string {
	re := regexp.MustCompile(`(?i)\sstyle\s*=\s*(?:"([^"]*)"|'([^']*)')`)
	return re.ReplaceAllStringFunc(s, func(m string) string {
		sub := re.FindStringSubmatch(m)
		body := ""
		if len(sub) >= 2 && sub[1] != "" {
			body = sub[1]
		} else if len(sub) >= 3 && sub[2] != "" {
			body = sub[2]
		}
		if body == "" {
			return ""        // ← 修复点 A：原 `return m` 会留下 style="" 空壳
		}

		var keep []string
		for _, decl := range strings.Split(body, ";") {
			d := strings.TrimSpace(decl)
			if d == "" {
				continue
			}
			kv := strings.SplitN(d, ":", 2)
			if len(kv) != 2 {
				continue
			}
			key := strings.ToLower(strings.TrimSpace(kv[0]))
			val := strings.TrimSpace(kv[1])

			if !inSafeStyleKeys(key) {          // ① key 白名单
				continue
			}
			if !safeStyleValue(key, val) {      // ② 值级校验（§5.3）
				continue
			}
			keep = append(keep, key+":"+val)
		}

		if len(keep) == 0 {
			return ""        // ← 修复点 B：原 69-75 行 `return m` 会整条放行危险样式
		}
		if len(sub) >= 2 && sub[1] != "" {
			return ` style="` + strings.Join(keep, ";") + `"`
		}
		return " style='" + strings.Join(keep, ";") + "'"
	})
}
```

**修复前后行为对比**（同一输入 `<p style="background:url(javascript:alert(1));color:red">x</p>`）：

| | 修复前 | 修复后 |
|---|---|---|
| 输出 | `<p style="background:url(javascript:alert(1));color:red">x</p>`（**整条原样保留**） | `<p style="color:red">x</p>` |
| 语义 | 危险即放行 | 危险声明被丢弃，安全声明保留 |

对比表同时说明：修复后**不是"一票否决整条 style"**，而是"逐声明过滤"——这是放开白名单后能同时保证"能力可用"与"安全可控"的关键。

### 5.3 值级校验 `safeStyleValue()`

```go
var styleDangerRe = regexp.MustCompile(`(?i)(expression|javascript|vbscript|behavior|@import|\\|/\*|url\s*\()`)

const maxStyleValueLen = 256

func safeStyleValue(key, val string) bool {
	if val == "" || len(val) > maxStyleValueLen {
		return false
	}
	// 危险函数 / 转义 / 注释 / 协议
	if styleDangerRe.MatchString(val) {
		return false
	}
	// 跳出属性上下文的三件套
	if strings.ContainsAny(val, `"'<>&`) {
		return false
	}
	switch key {
	case "color", "background-color", "border-color":
		return cssColorRe.MatchString(val)
	case "font-size", "line-height", "letter-spacing", "word-spacing",
		"width", "height", "max-width", "min-width", "text-indent",
		"margin", "margin-left", "margin-right", "margin-top", "margin-bottom",
		"padding", "padding-left", "padding-right", "padding-top", "padding-bottom":
		return cssLenRe.MatchString(val)
	case "font-family":
		return fontFamilyRe.MatchString(val)
	case "text-align":
		return oneOf(val, "left", "right", "center", "justify", "start", "end")
	case "font-weight":
		return cssWeightRe.MatchString(val)
	case "vertical-align":
		return oneOf(val, "baseline", "sub", "super", "top", "middle", "bottom", "text-top", "text-bottom")
	case "text-decoration", "text-decoration-line", "text-transform",
		"list-style", "list-style-type", "list-style-position",
		"border-style", "border-collapse", "white-space", "direction",
		"word-break", "overflow-wrap", "font-style", "background":
		return wordOnlyRe.MatchString(val)     // 枚举词，字母+连字符
	}
	// border / margin / padding 的简写（如 "1px solid #ccc"）
	return cssShorthandRe.MatchString(val) || cssLenRe.MatchString(val)
}

var (
	cssColorRe     = regexp.MustCompile(`(?i)^(#([0-9a-f]{3,8})|rgba?\([\d\s,.%]+\)|hsla?\([\d\s,.%deg]+\)|[a-z]{3,20}|transparent|currentcolor)$`)
	cssLenRe       = regexp.MustCompile(`(?i)^(-?\d+(\.\d+)?(px|pt|em|rem|%|vh|vw|ch|ex)?|auto|normal|inherit|initial|0)$`)
	cssWeightRe    = regexp.MustCompile(`(?i)^(normal|bold|bolder|lighter|[1-9]00)$`)
	fontFamilyRe   = regexp.MustCompile(`^[\p{Han}\w\s,'-]{1,120}$`)
	wordOnlyRe     = regexp.MustCompile(`(?i)^[a-z-]{1,32}$`)
	cssShorthandRe = regexp.MustCompile(`(?i)^(-?\d+(\.\d+)?(px|pt|em|rem|%)?\s+){0,3}[a-z#0-9(,).%\s-]{0,64}$`)
)
```

> **`strings.ContainsAny(val, "\"'<>&")` 是关键防线**：`;` 已在 split 阶段被切走，`\` 被 `styleDangerRe` 拦住，剩下的逃逸手段就是引号与尖括号。直接拒绝，比事后转义可靠。

### 5.4 属性白名单 `sanitizeAttrs()`（本次最大安全增量）

现状只删 `on*` 和拦伪协议，**对 `style` 以外的属性零限制**。Tiptap 会产大量 `<span>` / `<mark>` / `<sup>` / `<sub>` / `<td>`，攻击面随之扩大。新增一次属性遍历，只放行白名单属性：

```go
// 全局放行（所有标签）
var globalAttrWhitelist = map[string]bool{
	"style": true, "class": true, "id": true, "title": true, "dir": true, "lang": true,
	// 知识库业务约定属性（图片转正/缩进/对齐机制依赖，不可删！）
	"data-att-id": true, "data-temp-id": true, "data-att-name": true,
	"data-align": true, "data-indent": true, "data-type": true,
}

// 标签专属放行
var tagAttrWhitelist = map[string]map[string]bool{
	"a":     {"href": true, "target": true, "rel": true},
	"img":   {"src": true, "alt": true, "width": true, "height": true},
	"td":    {"colspan": true, "rowspan": true, "colwidth": true},
	"th":    {"colspan": true, "rowspan": true, "colwidth": true},
	"col":   {"span": true, "width": true},
	"ol":    {"start": true, "type": true},
	"table": {"border": true, "cellpadding": true, "cellspacing": true},
}

// 匹配 标签内 属性名=值（支持双引号/单引号/无引号）
var attrRe = regexp.MustCompile(`(?i)([a-zA-Z_:][-a-zA-Z0-9_:.]*)\s*=\s*("[^"]*"|'[^']*'|[^\s"'>]+)`)
```

**执行顺序**：`sanitizeAttrs()` 必须在 `stripUnsafeStyle()` **之前**——先删掉未授权属性（含带伪协议的 `href`），再收敛 `style`。若顺序颠倒，属性遍历会重新引入已被删的属性。

**⚠️ 与 `<img>` 的兼容**：`width`/`height` 为图片缩放的落库形态，必须在 `img` 的专属白名单内，否则缩放结果保存即丢。

### 5.7 `htmlToPlainText` 正则修正

### 5.9 前端 `safeHtml()` 同步改造

现状 932 行删除全部 style，与后端放开的白名单冲突。改为**与后端同口径的白名单过滤**：

```js
const SAFE_STYLE_KEYS = new Set([/* 与 §5.1 完全一致的 41 项 */])

function safeHtml(html) {
  if (!html) return ''
  let s = String(html)
  // 1) 删危险标签及内容（与后端同一清单）
  for (const t of ['script','style','iframe','object','embed','link','meta','form','svg','math','base','template','noscript','frame','frameset','applet','textarea','xmp','plaintext']) {
    s = s.replace(new RegExp('<\\s*' + t + '\\b[^>]*>[\\s\\S]*?<\\s*/\\s*' + t + '\\s*>', 'gi'), '')
    s = s.replace(new RegExp('<\\s*' + t + '\\b[^>]*/?>', 'gi'), '')
  }
  // 2) 删 on* 事件
  s = s.replace(/\son\w+\s*=\s*(?:"[^"]*"|'[^']*'|[^\s>]+)/gi, '')
  // 3) 拦伪协议
  s = s.replace(/(href|src|xlink:href|action|formaction)\s*=\s*(?:"|')?\s*(?:javascript|vbscript|data|file|blob|filesystem)\s*:/gi, '')
  // 4) 【改】style 白名单过滤（原为整条删除）
  s = s.replace(/\sstyle\s*=\s*(?:"([^"]*)"|'([^']*)')/gi, (m, d, q) => {
    const body = d ?? q ?? ''
    const keep = body.split(';').map(x => x.trim()).filter(Boolean).filter((decl) => {
      const i = decl.indexOf(':'); if (i < 0) return false
      const k = decl.slice(0, i).trim().toLowerCase()
      const v = decl.slice(i + 1).trim()
      if (!SAFE_STYLE_KEYS.has(k)) return false
      if (/expression|javascript|url\s*\(|@import|behavior|\\/i.test(v)) return false
      if (/["'<>&]/.test(v)) return false
      return true
    })
    return keep.length ? ` style="${keep.join(';')}"` : ''
  })
  return s
}
```

> **定位说明**：后端净化是**唯一防线**（落库前），前端 `safeHtml()` 是**纵深防御**（防历史脏数据 / 防有人绕过接口直改 DB）。两者口径必须一致，否则会出现"编辑器里看得见，详情页看不见"的诡异现象。

### 7.3 存量 HTML 兼容（核心适配）

**问题**：现有数据由 `execCommand` 产出，含 Tiptap 默认不认识的结构。

| 存量 HTML | 产生原因 | Tiptap 默认行为 | 处理 |
|---|---|---|---|
| `<font size="3" color="red" face="宋体">` | `execCommand('fontSize')` / Word 粘贴 | **丢弃属性**，只留文本 | `upgradeLegacyHtml()` 转 `<span style="...">` |
| `<p align="center">` | `execCommand('justifyCenter')` | `align` **丢失**（TextAlign 只读 style） | `LegacyHtmlCompat` 扩展 parseHTML 读 `align` |
| `<b>` / `<i>` / `<strike>` | 旧标签 | StarterKit 的 Bold 含 `b`/`strong`（OK）；Strike 需确认 | 实测确认，必要时加 ParseRule |
| `<h5>` / `<h6>` | formatBlock | `levels:[1,2,3,4]` → **降级为段落** | 用户已确认接受（H1–H4） |
| `<pre><code>` | insertCodeBlock | StarterKit 含 CodeBlock | 无需处理 |
| `<table border="1">` | insertTable | **TableRow/TableCell/TableHeader 未全注册 → 整表丢弃** | 必须四件全注册 |
| `<td>&nbsp;</td>` | 空单元格 | ProseMirror 不允许空单元格，自动补空段落 | 正常 |
| `<img data-att-id="12">` | 图片上传 | **属性丢失** | 自定义扩展（红线） |
| `<hr/>` / `<code>` | insertHr / insertInlineCode | StarterKit 内置 | 无需处理 |
| 正文里被转义存储的 `&lt;ol&gt;` | 历史脏数据 | 作为纯文本 | **不在本次范围** |

**核心机制：`upgradeLegacyHtml()` 在解析期转换**

```js
// editor/legacyHtml.js
export function upgradeLegacyHtml(html) {
  if (!html) return ''
  return String(html)
    // <font size="3" color="red" face="宋体"> → <span style="font-size:16px;color:red;font-family:宋体">
    .replace(/<font\b([^>]*)>/gi, (m, attrs) => {
      const size  = /\bsize\s*=\s*["']?(\d)["']?/i.exec(attrs)
      const color = /\bcolor\s*=\s*["']([^"']+)["']/i.exec(attrs)
      const face  = /\bface\s*=\s*["']([^"']+)["']/i.exec(attrs)
      const st = []
      if (size)  st.push(`font-size:${['10px','13px','16px','18px','24px','32px','48px'][size[1] - 1] || '16px'}`)
      if (color) st.push(`color:${color[1]}`)
      if (face)  st.push(`font-family:${face[1]}`)
      return st.length ? `<span style="${st.join(';')}">` : '<span>'
    })
    .replace(/<\/font>/gi, '</span>')
    // <p align="center"> → <p style="text-align:center">
    .replace(/<(p|h[1-6]|div|td|th)\b([^>]*?)\balign\s*=\s*["']?(left|center|right|justify)["']?/gi,
             (m, tag, pre, val) => `<${tag}${pre} style="text-align:${val}"`)
}
```

**接入点**：`useEditor({ content: upgradeLegacyHtml(props.modelValue) })` 与 `watch` 内的 `setContent(upgradeLegacyHtml(v), { emitUpdate: false })`。

> **零迁移的实现原理**：转换只在**解析期**发生，`getHTML()` 产出的是新形态（`<span style>` / `style="text-align"`）。因此**用户首次编辑保存后，该条目 HTML 自动完成归一化**，无需全库脚本。
