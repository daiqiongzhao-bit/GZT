## 一、结论速览

本次重构把知识库从「表单式编辑 + 弹窗查看」升级为「三栏工作台 + 所见即所得编辑器」，同时把后端富文本净化从「一刀切删样式」升级为「逐声明白名单过滤」。

**三个必须知道的结果：**

1. **编辑体验对齐 Word**：工具栏 40 项能力（字号/颜色/行距/缩进/表格/图片缩放/上下标/查找替换）全部实测可用，不再是"有按钮没功能"。
2. **零数据迁移**：存量 87 条知识条目全部正常读取，其中 8 条含旧格式（`<font>`、`align=`、`<h5>/<h6>`）的内容被自动归一化，**0 条内容丢失**。
3. **修复了 2 个会导致编辑器白屏的阻断级缺陷**（详见 §5），这两个缺陷在开发过程中真实出现并已定位根因。

## 五、过程中发现并修复的阻断级缺陷

以下是开发过程中真实出现、经定位后修复的问题。单独成节，因为它们具有**复用价值**——同类项目极可能踩到相同的坑。

### 缺陷 1：编辑器整体白屏（PasteImageUpload）

| 项 | 内容 |
|---|---|
| 严重级别 | 🔴 阻断（编辑器完全不可用） |
| 表象 | 点「编辑」后，工具栏与编辑区**双双空白**，页面其余部分完全正常 |
| 控制台 | `TypeError: Cannot read properties of undefined (reading 'state')` |
| 根因 | `addProseMirrorPlugins()` 返回了**裸对象** `{ key, props }`，而非 `new Plugin({...})` 实例。ProseMirror 内部读取 `plugin.spec.state`，裸对象没有 `.spec` |
| 定位方法 | 二分法：逐个从扩展数组移除自定义扩展，锁定到 `PasteImageUpload` |
| 修复 | 用 `new Plugin({...})` 包裹，import `Plugin` from `@tiptap/pm/state` |
| 风险提示 | 报错信息完全不提"插件"，容易误判为 Vue 或数据问题；**裸对象在语法上合法，只有运行时才炸** |

### 缺陷 2：撤销栈插件实例冲突（UndoRedo）

| 项 | 内容 |
|---|---|
| 严重级别 | 🔴 阻断（编辑器完全不可用） |
| 表象 | 同缺陷 1 |
| 控制台 | `RangeError: Adding different instances of a keyed plugin (history$)` |
| 根因 | `StarterKit` **已内置** `undoRedo`（plugin key `history$`）。代码又显式 `import { UndoRedo } from '@tiptap/extensions'` 并放入扩展数组，打包后是两个模块实例，同名 key 冲突 |
| 定位方法 | 二分法（移除自定义扩展后该错误浮现，说明是两个独立缺陷） |
| 修复 | 删除显式引入，撤销栈改为 `StarterKit.configure({ undoRedo: { depth: 200, newGroupDelay: 500 } })` |
| 风险提示 | **凡 Kit 已内置的能力都不要重复注册**（Table、Link 等同理） |

### 缺陷 3：单栏模式切换失灵（断点监听）

| 项 | 内容 |
|---|---|
| 严重级别 | 🟠 高（窄屏用户无法查看正文） |
| 表象 | 从 900px 直接缩到 700px，点击条目后详情栏不显示 |
| 根因 | 只监听了 `matchMedia('(max-width:1023px)')`。900px→700px 时该查询的 `matches` 一直是 `true`，不触发 `change` 事件，`kbNarrow` 停留在旧值 `false` |
| 修复 | 同时监听 `(min-width:1024px)` 与 `(max-width:819px)` 两个查询，任一变化都重算 |
| 风险提示 | 多断点布局**必须为每个断点注册独立监听**，不能只监听其中一个然后推导其余 |

### 缺陷 4：详情页样式全部消失（safeHtml）

| 项 | 内容 |
|---|---|
| 严重级别 | 🟠 高（所见非所得） |
| 表象 | 编辑时设的居中、字号、颜色、图片对齐，在详情页全部看不到 |
| 根因 | `safeHtml()` 最后一行 `s.replace(/\sstyle\s*=\s*"[^"]*"/gi, '')` **直接删掉整个 style 属性** |
| 修复 | 改为「逐声明过滤」：按 `;` 切分声明 → 键名过 41 项白名单 → 值过类型正则 → 安全的保留 |
| 附带加固 | 属性级白名单、引号感知的属性切分、href 正向白名单、实体解码后再判协议 |
| 风险提示 | 「为了安全把样式全删」是最常见的过度防御——安全与可用性可以兼得，前提是做**值级校验**而非**整体丢弃** |

### 缺陷 5：属性片段残留（净化顺序）

| 项 | 内容 |
|---|---|
| 严重级别 | 🔴 阻断（安全绕过） |
| 表象 | 输入 `<a href="javascript:alert(1)">` 输出 `<a alert(1)">` |
| 根因 | 旧的伪协议正则只匹配**前缀** `href="javascript:`，`ReplaceAllString` 只删这一段，剩下 `alert(1)">` 被下一次解析当成**新属性** |
| 修复 | ① 调整顺序：整条属性删除的 `enforceHrefWhitelist()` 先于协议拦截；② 正则改为匹配**整条属性**（含引号包裹的值） |
| 风险提示 | 净化函数中**处理顺序是承载语义的**，重排顺序可能重新引入漏洞；已加回归测试锁定 |
| 回归测试 | `TestSanitize_ProtoNoFragmentResidue` |
